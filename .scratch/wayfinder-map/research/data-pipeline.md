## 1. Architecture Overview

The data pipeline moves data from the flyer source (`www.primarycaresafetynet.ie`) through a transformation layer into the app's `services.json`, which is then cached locally for offline use.

```
┌─────────────────┐     ┌──────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│  flyer-data.json │────▶│  Transform Layer  │────▶│  services.json   │────▶│  Local Storage  │
│  (raw scraped)   │     │  (validation,     │     │  (app data file) │     │  (IndexedDB +   │
│  Source: primary  │     │   enrichment)     │     │  GitHub Pages     │     │   Cache API)    │
│  care safety net  │     └──────────────────┘     └──────────────────┘     └─────────────────┘
└─────────────────┘                                                           │        │
                                                                              │        ▼
                                                                              │  Service Worker
                                                                              │  (StaleWhileRevalidate)
                                                                              │        │
                                                                              ▼        ▼
                                                                     ┌─────────────────────┐
                                                                     │  User Device (PWA)  │
                                                                     │  - Offline access   │
                                                                     │  - Background sync  │
                                                                     │  - Cache updates    │
                                                                     └─────────────────────┘
```

### Pipeline Stages

| Stage        | Input                                        | Output                      | Description                               |
| ------------ | -------------------------------------------- | --------------------------- | ----------------------------------------- |
| 1. Scrape    | HTML from primarycaresafetynet.ie            | `flyer-data.json`           | Extract structured data from flyer        |
| 2. Validate  | `flyer-data.json`                            | Validated `flyer-data.json` | Check all fields, flag missing data       |
| 3. Transform | Validated `flyer-data.json`                  | `services.json` (partial)   | Map flyer schema → ServiceLocation schema |
| 4. Enrich    | Transformed data + external sources          | `services.json` (full)      | Add coordinates, contact info, metadata   |
| 5. Merge     | Enriched new data + existing `services.json` | Final `services.json`       | Merge with existing 14-service dataset    |
| 6. Deploy    | `services.json`                              | GitHub Pages                | Static file served to PWA                 |
| 7. Cache     | `services.json` from network                 | IndexedDB + Cache API       | Local storage populated by service worker |

## 2. Data Sources

### 2.1 Primary Source: Flyer Data

- **File:** `.scratch/wayfinder-map/research/flyer-data.json`
- **Source URL:** `www.primarycaresafetynet.ie`
- **Extracted:** 2026-09-14
- **Content:** 5 Day Support Centres + 5 Free Doctor Clinics
- **Fields present:** id, name, address, hours, services, services_categories, healthcare_services, special_notes
- **Fields missing:** phone, email, website, coordinates (lat/long), walk-in availability, appointment availability

### 2.2 Secondary Source: Existing App Data

- **File:** `src/lib/data/services.json`
- **Generated by:** Dublin Lifeline Pipeline v3.1.0
- **Content:** 14 service locations with full schema (coordinates, contact info, etc.)
- **Last updated:** 2026-09-13T09:53:39.731Z
- **Metadata:** Tracks pipeline runs, sync schedules, diffs

### 2.3 Gap Analysis Summary

From `gap-analysis.md`, the flyer data is missing:

- Coordinates (lat/long) for all 10 locations
- Phone numbers for all 10 locations
- Website URLs for all 10 locations
- Email addresses
- Walk-in vs appointment distinction
- Specific GP clinic hours
- MHU schedule details
- Accessibility information

### 2.4 Data Enrichment Strategy

Since the flyer lacks coordinates and contact info, the pipeline must enrich data from secondary sources:

| Missing Field          | Enrichment Source                                        | Method                  |
| ---------------------- | -------------------------------------------------------- | ----------------------- |
| Coordinates (lat/long) | OpenStreetMap Nominatim API                              | Geocode address strings |
| Phone numbers          | Web scraping of primarycaresafetynet.ie or manual lookup | Per-location extraction |
| Email/website          | Same as above or manual entry                            | Per-location extraction |
| GP clinic schedules    | Manual follow-up with source                             | Human input required    |

**Important:** Coordinates and contact enrichment must happen in the transform step, not in the scraper itself. The scraper produces raw flyer data; the pipeline enriches it.

### 3.3 Hours Schema Conversion

The flyer uses a different hours format than the app. Conversion rules:

**Flyer format:** `"08:30-22:30"` or `"08:30-11:30, 12:30-15:00"` or `null`

**App format:** `Record<string, string>` with keys like `"mon-fri"`, `"sat"`, `"sun"` or individual days

```
Flyer → App conversion:
- "monday": "08:30-22:30" → hours.monday = "08:30-22:30"
- "saturday": null → hours.saturday = "closed"
- "sunday": "09:30-14:30, 16:30-22:30" → hours.sunday = "09:30-14:30, 16:30-22:30"
```

**For doctor clinics:**

```
Flyer: { "mon_fri": "Appointment and walk-in times available" }
App:  { "mon-fri": "09:30-16:30" }  (approximate, needs human verification)
```

**Critical gap:** Doctor clinic hours are NOT specified in the flyer. The pipeline must either:

- Use the parent Day Support Centre's hours as a proxy
- Leave hours as `null`/empty with a note
- Require human input for exact times

### 5.2 Detailed Transform Logic

#### Step 1: Validation

```typescript
function validateFlyerData(data: any): ValidationResult {
	const errors: string[] = [];
	const warnings: string[] = [];

	// Check required top-level fields
	if (!data.source) errors.push("Missing 'source' field");
	if (!data.extracted_date) errors.push("Missing 'extracted_date' field");
	if (!data.day_support_centres?.length) errors.push('No day_support_centres');
	if (!data.free_doctor_clinics?.length) errors.push('No free_doctor_clinics');

	// Validate each location
	for (const centre of data.day_support_centres) {
		if (!centre.id) errors.push(`Missing id in centre`);
		if (!centre.name) errors.push(`Missing name in ${centre.id}`);
		if (!centre.address) errors.push(`Missing address in ${centre.id}`);
		if (!centre.hours && centre.hours !== null) warnings.push(`${centre.id}: hours is null`);
		if (!centre.services?.length) errors.push(`${centre.id}: no services`);
	}

	// Validate doctor clinics
	for (const clinic of data.free_doctor_clinics) {
		if (!clinic.id) errors.push('Missing id in clinic');
		if (!clinic.address) errors.push(`Missing address in ${clinic.id}`);
	}

	// Check for missing critical fields
	const allLocations = [...data.day_support_centres, ...data.free_doctor_clinics];
	for (const loc of allLocations) {
		if (!loc.phone) warnings.push(`${loc.id}: missing phone`);
		if (!loc.latitude) warnings.push(`${loc.id}: missing coordinates`);
	}

	return { valid: errors.length === 0, errors, warnings };
}
```

#### Step 2: Transform

```typescript
function transformCentreToLocation(centre: DaySupportCentre): Partial<ServiceLocation> {
	return {
		id: centre.id,
		name: centre.name,
		address: centre.address,
		phone: centre.phone || '',
		email: centre.email || '',
		website: centre.website || '',
		hours: convertHours(centre.hours), // See §3.3
		tags: [...centre.services_categories, ...centre.healthcare_services],
		services: mapServicesToSlugs(centre.services),
		category: assignCategory(centre),
		latitude: 0, // Will be filled by enrichment
		longitude: 0, // Will be filled by enrichment
		description: generateDescription(centre),
		lastVerified: centre.extracted_date || new Date().toISOString().split('T')[0],
		dataSource: 'scraped',
		scrapeSuccess: true,
		lastScraped: new Date().toISOString()
	};
}
```

#### Step 3: Enrichment

```typescript
async function enrichLocations(locations: Partial<ServiceLocation>[]): Promise<ServiceLocation[]> {
	for (const loc of locations) {
		if (!loc.latitude || !loc.longitude) {
			const coords = await geocodeAddress(loc.address);
			loc.latitude = coords.lat;
			loc.longitude = coords.lng;
		}
		if (!loc.phone || !loc.email || !loc.website) {
			const enriched = await lookupContactInfo(loc.name, loc.address);
			loc.phone = loc.phone || enriched.phone || '';
			loc.email = loc.email || enriched.email || '';
			loc.website = loc.website || enriched.website || '';
		}
		loc.description = loc.description || generateDescription(loc);
	}
	return locations;
}
```

#### Step 4: Merge

```typescript
function mergeWithExisting(
	newLocations: ServiceLocation[],
	existing: ServiceLocation[]
): MergeResult {
	const existingIds = new Set(existing.map((s) => s.id));
	const additions: ServiceLocation[] = [];
	const updates: ServiceLocation[] = [];
	const deletions: string[] = [];

	for (const newLoc of newLocations) {
		const existingIdx = existing.findIndex((s) => s.id === newLoc.id);
		if (existingIdx === -1) {
			additions.push(newLoc);
		} else {
			// Compare fields to detect changes
			const diffs = detectChanges(existing[existingIdx], newLoc);
			if (diffs.length > 0) {
				updates.push({ ...newLoc, lastScraped: new Date().toISOString() });
			}
		}
	}

	// Detect deleted locations
	for (const existingLoc of existing) {
		if (!newLocations.find((n) => n.id === existingLoc.id)) {
			deletions.push(existingLoc.id);
		}
	}

	return { additions, updates, deletions, merged: [...updates, ...additions] };
}
```

#### Step 5: Output

```typescript
function generateServicesJson(
	newLocations: ServiceLocation[],
	existing: ServicesData
): ServicesData {
	const merged = mergeWithExisting(newLocations, existing.services);
	const allServices = [
		...existing.services.filter((s) => !merged.deletions.includes(s.id)),
		...merged.merged
	];

	const categories = [...new Set(allServices.map((s) => s.category))].sort();
	const now = new Date().toISOString();

	return {
		version: incrementVersion(existing.version),
		lastUpdated: now,
		generatedBy: 'Dublin Lifeline Pipeline',
		services: allServices,
		metadata: {
			source: 'Dublin Lifeline Pipeline (merged)',
			totalServices: allServices.length,
			categories,
			coverage: 'Dublin City Centre',
			nextSync: getNextSyncDate(),
			pipelineRun: now,
			differencesDetected: merged.updates.length + merged.additions.length,
			additions: merged.additions.length,
			updates: merged.updates.length,
			deletions: merged.deletions.length
		}
	};
}
```

## 6. Local Storage Setup

### 6.1 Storage Architecture

The PWA uses two local storage mechanisms:

| Storage          | Type                | Purpose                                          | Capacity     |
| ---------------- | ------------------- | ------------------------------------------------ | ------------ |
| **IndexedDB**    | Structured database | Full `services.json` dataset for offline queries | ~50MB+       |
| **Cache API**    | HTTP cache          | `services.json` file for service worker caching  | Configurable |
| **localStorage** | Key-value           | User preferences, low-data mode toggle           | ~5MB         |

### 6.2 IndexedDB Setup

The service worker populates IndexedDB with the flyer dataset on installation.

**Database name:** `dcs-directory`
**Store name:** `services`
**Key:** `id` (service location ID)

```typescript
// In service worker (src/service-worker.js):
const DB_NAME = 'dcs-directory';
const DB_VERSION = 1;
const STORE_NAME = 'services';

async function initDB() {
	const db = await openDB(DB_NAME, DB_VERSION, {
		upgrade(db) {
			if (!db.objectStoreNames.contains(STORE_NAME)) {
				const store = db.createObjectStore(STORE_NAME, { keyPath: 'id' });
				store.createIndex('category', 'category', { unique: false });
				store.createIndex('name', 'name', { unique: false });
				store.createIndex('latitude', 'latitude', { unique: false });
				store.createIndex('longitude', 'longitude', { unique: false });
			}
		}
	});
	return db;
}

async function populateDB(services: ServiceLocation[]) {
	const db = await initDB();
	const tx = db.transaction(STORE_NAME, 'readwrite');
	const store = tx.objectStore(STORE_NAME);
	for (const service of services) {
		await store.put(service);
	}
	await tx.done;
}
```

### 6.3 Cache API Setup

The service worker caches `services.json` using `StaleWhileRevalidate`:

```typescript
// In vite.config.ts workbox config:
{
  urlPattern: /\/services\.json/,
  handler: 'StaleWhileRevalidate',
  options: {
    cacheName: 'data-json',
    expiration: {
      maxEntries: 10,
      maxAgeSeconds: 7 * 24 * 60 * 60 // 7 days
    }
  }
}
```

### 6.4 Client-Side Data Access

The app loads data from two sources depending on connectivity:

```typescript
// In +page.server.ts or client-side load:
export async function load() {
	try {
		const response = await fetch('/services.json');
		if (response.ok) {
			const data = await response.json();
			// Populate IndexedDB for offline access
			await populateDB(data.services);
			return { services: data.services, source: 'network' as const };
		}
	} catch {
		// Offline — read from IndexedDB
		const db = await initDB();
		const services = await db.getAll('services');
		return { services, source: 'cache' as const };
	}
}
```


## 7. Sync Mechanism

### 7.1 Sync Architecture

The sync mechanism ensures local data stays current with the remote `services.json` on GitHub Pages.

```
┌─────────────────────────────────────────────────────┐
│              SYNC TRIGGER                            │
├─────────────────────────────────────────────────────┤
│ 1. Service worker install/update                     │
│ 2. User pulls-to-refresh                             │
│ 3. Scheduled: every 7 days (StaleWhileRevalidate)   │
│ 4. Network status change (online → offline → online) │
│ 5. Manual: user clicks "Update data"                 │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────┐
│              SYNC EXECUTION                          │
├─────────────────────────────────────────────────────┤
│ 1. Fetch services.json from network                  │
│ 2. Compare version with cached version               │
│ 3. If version differs:                               │
│    a. Update Cache API with new JSON                 │
│    b. Update IndexedDB with new service records      │
│    c. Broadcast DATA_UPDATE to clients               │
│    d. Show toast notification                        │
│ 4. If version matches:                               │
│    a. Data is current, no action needed              │
└─────────────────────────────────────────────────────┘
```

### 7.2 Version-Based Sync

The `services.json` contains a `version` field (semver). The sync compares versions:

```typescript
// In service worker:
self.addEventListener('activate', async (event) => {
	const cachedResponse = await caches.match('/services.json');
	if (cachedResponse) {
		const cachedData = await cachedResponse.json();
		const cachedVersion = cachedData.version;

		const networkResponse = await fetch('/services.json');
		const networkData = await networkResponse.json();
		const networkVersion = networkData.version;

		if (networkVersion !== cachedVersion) {
			// Data has changed — update caches
			const cache = await caches.open('data-json');
			await cache.put('/services.json', networkResponse.clone());

			// Update IndexedDB
			await populateDB(networkData.services);

			// Notify clients
			const clients = await self.clients.matchAll();
			clients.forEach((client) => {
				client.postMessage({
					type: 'DATA_UPDATE',
					version: networkVersion,
					lastUpdated: networkData.lastUpdated,
					additions: networkData.metadata.additions,
					updates: networkData.metadata.updates,
					deletions: networkData.metadata.deletions
				});
			});
		}
	}
});
```

### 7.5 Stale-While-Revalidate for Data Freshness

The service worker uses `StaleWhileRevalidate` for `services.json`:

- **Online:** Serve cached data immediately, fetch fresh data in background
- **Offline:** Serve cached data from Cache API
- **Fresh data detected:** Notify user via toast

```typescript
// Runtime caching config in vite.config.ts:
{
  urlPattern: /\/services\.json/,
  handler: 'StaleWhileRevalidate',
  options: {
    cacheName: 'data-json',
    expiration: {
      maxEntries: 10,
      maxAgeSeconds: 7 * 24 * 60 * 60
    },
    plugins: [{
      cachedResponseWillBeUsed: async ({ cachedResponse }) => {
        if (!cachedResponse) return cachedResponse;
        const data = await cachedResponse.clone().json();
        self.__cachedVersion = data.version;
        return cachedResponse;
      },
      networkResponseWillBeUsed: async ({ networkResponse }) => {
        const data = await networkResponse.clone().json();
        if (self.__cachedVersion && data.version !== self.__cachedVersion) {
          // Data updated — broadcast to clients
          const clients = await self.clients.matchAll();
          clients.forEach(client => {
            client.postMessage({ type: 'DATA_UPDATE', version: data.version });
          });
        }
        return networkResponse;
      }
    }]
  }
}
```

## 8. Data Validation

### 8.1 Validation Rules

All data must pass validation before being written to `services.json`.

#### Location-Level Validation

| Rule     | Field       | Type                | Severity  |
| -------- | ----------- | ------------------- | --------- |
| Required | `id`        | string, non-empty   | **Error** |
| Required | `name`      | string, non-empty   | **Error** |
| Required | `address`   | string, non-empty   | **Error** |
| Required | `latitude`  | number, -90 to 90   | **Error** |
| Required | `longitude` | number, -180 to 180 | **Error** |
| Required | `category`  | string, non-empty   | **Error** |
| Required | `services`  | array, non-empty    | **Error** |
| Warning  | `phone`     | string or empty     | Warning   |
| Warning  | `hours`     | object or null      | Warning   |
| Warning  | `email`     | string or empty     | Warning   |
| Warning  | `website`   | string or empty     | Warning   |

#### Hours Validation

| Rule          | Description                                                   | Severity           |
| ------------- | ------------------------------------------------------------- | ------------------ |
| Format check  | Hours must be `"HH:MM-HH:MM"` or `"HH:MM-HH:MM, HH:MM-HH:MM"` | Error if malformed |
| Time range    | End time must be after start time                             | Warning if invalid |
| Day coverage  | At least some days must have hours (or null with note)        | Warning            |
| Null handling | `null` hours must have `special_notes` explaining why         | Warning            |

#### Services Validation

| Rule           | Description                                   | Severity       |
| -------------- | --------------------------------------------- | -------------- |
| Non-empty      | `services` array must have at least one entry | **Error**      |
| Valid slugs    | Service names must be valid slug strings      | Warning if not |
| No duplicates  | No duplicate service names within a location  | Warning        |
| Category match | `category` must match a known category        | Warning        |

#### Healthcare Clinic Validation

| Rule                                           | Description                                      | Severity               |
| ---------------------------------------------- | ------------------------------------------------ | ---------------------- |
| `location_id` must reference existing location | Doctor clinics must link to a Day Support Centre | **Error** (unless MHU) |
| `schedule` must be present                     | GP clinics must have schedule data               | Warning                |
| `appointment_available` or `walk_in_available` | At least one must be true or null                | Warning                |

### 8.2 Validation Implementation

```typescript
// scripts/validate.ts
interface ValidationResult {
	valid: boolean;
	errors: ValidationError[];
	warnings: ValidationError[];
}

interface ValidationError {
	location: string;
	field: string;
	message: string;
	severity: 'error' | 'warning';
}

function validateServiceLocation(loc: Partial<ServiceLocation>): ValidationError[] {
	const errors: ValidationError[] = [];

	if (!loc.id || loc.id.trim() === '') {
		errors.push({
			location: loc.name || 'unknown',
			field: 'id',
			message: 'ID is required',
			severity: 'error'
		});
	}
	if (!loc.name || loc.name.trim() === '') {
		errors.push({
			location: loc.id || 'unknown',
			field: 'name',
			message: 'Name is required',
			severity: 'error'
		});
	}
	if (!loc.address || loc.address.trim() === '') {
		errors.push({
			location: loc.id || 'unknown',
			field: 'address',
			message: 'Address is required',
			severity: 'error'
		});
	}
	if (typeof loc.latitude !== 'number' || loc.latitude < -90 || loc.latitude > 90) {
		errors.push({
			location: loc.id || 'unknown',
			field: 'latitude',
			message: 'Latitude must be -90 to 90',
			severity: 'error'
		});
	}
	if (typeof loc.longitude !== 'number' || loc.longitude < -180 || loc.longitude > 180) {
		errors.push({
			location: loc.id || 'unknown',
			field: 'longitude',
			message: 'Longitude must be -180 to 180',
			severity: 'error'
		});
	}
	if (!loc.category || loc.category.trim() === '') {
		errors.push({
			location: loc.id || 'unknown',
			field: 'category',
			message: 'Category is required',
			severity: 'error'
		});
	}
	if (!loc.services || loc.services.length === 0) {
		errors.push({
			location: loc.id || 'unknown',
			field: 'services',
			message: 'At least one service is required',
			severity: 'error'
		});
	}
	if (!loc.phone) {
		errors.push({
			location: loc.id || 'unknown',
			field: 'phone',
			message: 'Phone number missing',
			severity: 'warning'
		});
	}
	if (!loc.email) {
		errors.push({
			location: loc.id || 'unknown',
			field: 'email',
			message: 'Email missing',
			severity: 'warning'
		});
	}
	if (!loc.website) {
		errors.push({
			location: loc.id || 'unknown',
			field: 'website',
			message: 'Website missing',
			severity: 'warning'
		});
	}

	return errors;
}
```

## 9. Deployment & Build Integration

### 9.1 Build Pipeline

```
Source: flyer-data.json
    │
    ▼
npm run pipeline (transform + enrich + merge)
    │
    ▼
Output: src/lib/data/services.json + static/services.json
    │
    ▼
npm run validate (verify output)
    │
    ▼
vite build (generate static HTML + assets)
    │
    ▼
@vite-pwa/sveltekit generates service worker
    │
    ▼
@vite-pwa/sveltekit generates precache manifest
    │
    ▼
Deploy to GitHub Pages (gh-pages branch or actions/upload-pages-artifact)
    │
    ▼
Service Worker installs, precaches services.json, populates IndexedDB
```

### 9.2 Dual JSON Output

The pipeline must write to both locations:

| File            | Purpose                                 | Path                         |
| --------------- | --------------------------------------- | ---------------------------- |
| Source of truth | App imports during SSR/build            | `src/lib/data/services.json` |
| Static serving  | Served by GitHub Pages for client fetch | `static/services.json`       |

Both files must be identical. The pipeline writes to `src/lib/data/services.json`, and the build copies it to `static/services.json` via the static adapter.

### 9.3 Service Worker Integration

The `@vite-pwa/sveltekit` plugin automatically:

1. Generates the service worker with the precache manifest
2. Includes `services.json` in the precache (via `globPatterns`)
3. Sets up `StaleWhileRevalidate` for runtime caching of `services.json`
4. Handles cache versioning via `$service-worker` version module

### 9.4 Version Bump Strategy

When the pipeline produces new data:

- Increment version (e.g., `3.1.0` → `3.2.0` if additions/updates)
- Update `lastUpdated` to current timestamp
- Update `metadata.pipelineRun` to current timestamp
- Update `metadata.nextSync` to pipelineRun + 7 days
- Update `metadata` diff counts (additions, updates, deletions)

### 10.1 HITL — Requires Human Input

The following items **cannot** be fully automated and require human decisions:

| #   | Decision                                                                 | Why                                                                                                                 | Impact                                          |

| 2   | **Provide coordinates** (lat/long) for all locations                     | Addresses can be geocoded automatically, but accuracy may vary; manual verification recommended                     | High — map functionality depends on this        |
| 3   | **Confirm GP clinic hours**                                              | The flyer says "Mon-Fri with appointment and walk-in times" but does not specify exact hours                        | High — users need to know when clinics are open |
